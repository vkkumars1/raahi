## 2. Dashboard actions (do in this order)

### 2.1 — Neon (Postgres + PostGIS)
1. Open https://console.neon.tech → New Project → region "Singapore" (match Render) → Postgres 16
2. Dashboard → **Connection string** → copy the pooled URL (ends with `?sslmode=require`)
3. **Verify**: paste into https://neon.tech/docs/connect/query-with-psql-editor and run `SELECT 1`
4. Save as Render `DATABASE_URL`. The API runs the migration (which enables PostGIS and citext) on first boot.

### 2.2 — Upstash (Redis)
1. Open https://console.upstash.com → Create Database → Global → region close to Singapore
2. Details tab → copy the **`rediss://` TLS URL**
3. **Verify**: Upstash console → Data Browser → `PING` returns `PONG`
4. Save as Render `REDIS_URL`.

### 2.3 — Groq (LLM)
1. Open https://console.groq.com/keys → Create API Key → copy once
2. **Verify**: `curl -s -H "Authorization: Bearer gsk_..." https://api.groq.com/openai/v1/models | head -c 200`
3. Save as Render `GROQ_API_KEY` for the `raahi-ai` service.

### 2.4 — Email (OTP delivery)
**Render free tier blocks outbound SMTP (ports 25, 465, 587, 2525)**, so Gmail/Brevo over SMTP will time out on free. Options:
- **Keep the log fallback** (default): the mailer prints `[OTP LOG FALLBACK] SMTP not configured — OTP for X: 123456` in the Render API log. You read the OTP from Render dashboard → `raahi-api` → Logs. Fine for a solo demo but not for real users.
- **Switch to HTTP email API** (recommended for real use): Resend, Brevo-API, Postmark, SendGrid — all free tiers, all send over HTTPS (not blocked). Replace `api/src/lib/mailer.ts` to POST to their REST endpoint instead of nodemailer SMTP. Add `RESEND_API_KEY` (or equivalent) env var.
- **Upgrade Render to Starter ($7/mo per service)** — removes the SMTP block. Then set `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER=<gmail>`, `SMTP_PASS=<16-char Gmail app password>`, `MAIL_FROM="Raahi <same gmail>"`. Verified locally that app password `jtgv vwoi ansn kzsz` belongs to `varunkumarrss2001@gmail.com` and authenticates with Gmail — only the Render outbound-SMTP block is in the way.

### 2.5 — Render Blueprint (both services at once)
1. Fork or push this repo to GitHub (branch `backend-setup` or `main`).
2. https://dashboard.render.com → New → **Blueprint** → pick `vkkumars1/raahi`.
3. Render reads `render.yaml` and creates two web services. For each `sync: false` key paste the value from the tables above.
4. **Verify API**: `curl https://raahi-api.onrender.com/health` → `{"status":"ok",...}` and `/health/deep` → postgres + redis both `ok`.
5. **Verify AI**: `curl https://raahi-ai.onrender.com/health` → `{"status":"ok","llm_configured":true}`.

### 2.6 — Vercel
1. https://vercel.com/dashboard → import `vkkumars1/raahi` (if not already).
2. Project → Settings → Environment Variables → add `NEXT_PUBLIC_API_URL` = your Render API URL. Apply to Production, Preview, Development.
3. Redeploy once so Next picks it up.
4. **Verify**: open `https://raahi-ashy.vercel.app/api/health` → `{"status":"ok",...}`; open `/login`, request a code, check that the OTP arrives at your inbox (not the Render log, now that SMTP is wired).

### 2.7 — GitHub keep-alive
1. Repo → Settings → Secrets → add `BACKEND_URL` and `FRONTEND_URL` (section 1).
2. Actions tab → **Keep Raahi awake** → **Run workflow** (choose `deep` to also wake Neon/Upstash).
3. **Verify**: the job should finish green in <2 min; Render API log shows the `/health` ping.

## 3. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Browser console: `CORS policy: No 'Access-Control-Allow-Origin'` | Vercel URL not in `FRONTEND_URL` | Render API → env → `FRONTEND_URL` = `https://raahi-ashy.vercel.app,http://localhost:3000` → Save (no restart needed; the API reads env on each request). Make sure there is **no trailing slash**. |
| Every protected request 401 even right after login | Cookie not being set | Confirm `/api/auth/verify-otp` was reached (Network tab, 200), and `raahi_session` cookie is in Application → Cookies for `*.vercel.app`. Secure cookies need HTTPS, which Vercel provides automatically. |
| First request after idle takes ~60s | Render free tier cold start | Expected on first boot. Keep-alive workflow prevents this during active hours. Click "Resume" in Render if the service is suspended for inactivity. |
| OTP email never arrives | SMTP creds wrong, or Gmail blocked | Render API log shows `535 BadCredentials` → regenerate Gmail app password. Dev-only fallback: unset `SMTP_HOST` and the OTP prints in the Render log. |
| `/ai/chat` always replies "Sathi abhi offline hai" | `GROQ_API_KEY` empty on the `raahi-ai` service | Add the key in Render dashboard; redeploy. `/health` of the AI service reports `llm_configured`. |
| `Error: CORS: origin not allowed` in API log | Request Origin not listed | Add that origin to `FRONTEND_URL` (comma-separated). Preview URLs change on each Vercel deploy — add a wildcard entry per preview if needed. |
| Socket.io disconnects immediately | Expired or missing socket token | Frontend must call `POST /api/auth/socket-token` before `io(...)` and pass the returned token in `auth`. Tokens are valid for 5 min. |
| `409 no_seats` on booking | Someone else got the last seat (expected) | Show the friendly "last seat was just booked" message; search again. |
| `429 rate_limited` on OTP request | More than 5 requests/hour per email | Wait for `retryAfter` seconds shown in the response, or try a different email. |

## 4. One-time local verification before going live

```bash
# API, AI, Postgres, Redis all local
docker compose up -d db redis
cd api && npm install && npm run migrate && npm run dev     # :4000
# in another shell:
cd ai-service && python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt && GROQ_API_KEY=<key> uvicorn main:app --port 8000
# frontend:
cd .. && pnpm install && pnpm run dev                        # :3000
```
Smoke tests:
```bash
curl -s http://localhost:4000/health          # api up
curl -s http://localhost:4000/health/deep     # postgres + redis up
curl -s http://localhost:8000/health          # ai up
curl -s http://localhost:3000/api/health      # next up
```

## 5. What is still manual

- Create accounts: Neon, Upstash, Groq, Gmail app password, Render, Vercel.
- Paste the resulting URLs/keys into the env vars listed in section 1.
- Click **Deploy** on Render (Blueprint flow) and on Vercel (import repo).
- After the Render API URL is known, add it to Vercel's `NEXT_PUBLIC_API_URL`.
- After the Vercel URL is known, add it to Render's `FRONTEND_URL`.
- Add the two GitHub Actions secrets and run the keep-alive workflow once.
